Overview

Fraud is rare (about 1% of bank account applications in our dataset), so fraud detectors learn the normal class well and the fraud class poorly. A common fix is to create artificial fraud cases with generative AI, but this is rarely evaluated rigorously.

BankSynth AI asks a simple question: do synthetic frauds actually help detect real frauds, and is the gain worth the cost compared with simple methods, without hurting fairness or leaking training data?

The platform:

trains four tabular generators (statistical, GAN, VAE and diffusion) on the training frauds only;
compares them against three simple baselines (no rebalancing, class weighting, SMOTE-NC);
evaluates synthetic data on fidelity, detectability, validity, diversity, utility and privacy;
runs a leak-free benchmark (temporal split, 5 seeds, 2 detectors, bootstrap confidence intervals, test set opened once);
measures fairness across age groups;
explains alerts with SHAP and a verified LLM assistant;
presents everything in a Streamlit app.

A negative result (no generator beats the simple baselines) is a valid outcome and will be reported as such.

Research questions
ID	Question	Measure
Q1 — Utility	Does adding synthetic frauds improve PR-AUC and recall at 5% FPR vs. class weighting and SMOTE-NC?	PR-AUC, recall @ 5% FPR
Q2 — Fidelity	Which generator best reproduces the distributions and dependencies of the fraud class?	KS, Wasserstein, TVD, C2ST
Q3 — Fairness	Does augmentation reduce or widen false-positive gaps between age groups?	FPR ratio
Q4 — Privacy	Are synthetic rows too close to training rows?	DCR, exact copies
Q5 — Explanation	Can an LLM produce explanations faithful to SHAP without inventing factors?	Faithfulness rate

H1: at least one generator improves PR-AUC over the best simple baseline. H0: no generator beats class weighting or SMOTE-NC.

Dataset

Bank Account Fraud (BAF) — Base variant, published by Feedzai at NeurIPS 2022.

About 1M bank account applications over 8 months (month 0–7), about 1% fraud (fraud_bool).
Interpretable features (e.g. customer_age, income, employment_status, name_email_similarity, device_os), which makes fairness analysis and readable explanations possible.
Sources: Kaggle · GitHub (feedzai/bank-account-fraud)
License: CC BY-NC-SA 4.0 — non-commercial use, attribution required, derived data published under the same license.

BAF was itself generated by Feedzai with a GAN trained on real data. We therefore generate synthetic data from already-synthetic data; this limitation is discussed in the report.

The raw data is not versioned. See Installation to download it. Its SHA-256 fingerprint is recorded in docs/data_card.md.

Temporal split
Partition	Months	Use
Train	0–5	Preprocessing fit, generator training (frauds only), detector training
Validation	6	Ratio selection, hyperparameter tuning, decision threshold
Test	7	Final evaluation, opened once

The split follows Feedzai's official notebook and will be confirmed after the EDA (target: ≥ 500 frauds in test).

Methods compared
Family	Method	Idea	Library
None	No rebalancing	Detector trained on raw data	LightGBM
Weighting	class_weight	A missed fraud costs more than a false alarm	LightGBM
Interpolation	SMOTE-NC	New frauds created between existing ones	imbalanced-learn
Statistical	Gaussian Copula	Model each variable, then their correlations	SDV
GAN	CTGAN	A generator and a discriminator compete	SDV
VAE	TVAE	Encode frauds into a latent code, decode new ones	SDV
Diffusion	TabDDPM	Learn to remove noise step by step; generate from pure noise	synthcity

All generators are trained on the training frauds only, with library defaults, a fixed number of epochs (identical for CTGAN and TVAE) and a fixed, documented number of diffusion steps for TabDDPM.

Benchmark protocol
Strategies (11)
Code	Strategy	Detector training data
E1a	Raw baseline	Real train
E1b	Class weighting	Real train, weighted frauds
E2	SMOTE-NC	Real train + interpolated frauds
E3-GC / E3-CT / E3-TV / E3-DF	Augmentation	Real train + synthetic frauds (Copula / CTGAN / TVAE / TabDDPM)
E4-GC / E4-CT / E4-TV / E4-DF	TSTR	Synthetic frauds + real normal applications

Each strategy is evaluated with 2 detectors: logistic regression (interpretable reference) and LightGBM (main model).

Three phases
Phase	Runs	Data	Output
A — Selection	SMOTE-NC + 4 generators × 3 ratios (+100%, +300%, +1000%), 1 seed, LightGBM	train → validation	Best ratio per method
B — Robustness	11 strategies × 5 seeds × 2 detectors = 110 models	train → validation	Decision threshold per model
C — Final evaluation	The 110 models of phase B + 1,000 bootstrap resamples	test, once	Final results
Fairness rules between strategies
Same partitions and test month for every strategy.
LightGBM hyperparameters tuned once on validation with E1b (random search, 20 trials), then frozen.
Same number of added frauds for SMOTE-NC and generators at equal ratio.
Threshold chosen on validation for a 5% false-positive rate.
Seed n controls both generator and detector (seeds 0–4).
Decision rule

gain = PR-AUC(E3) − PR-AUC(best of E1a, E1b, E2), at equal seed. A generator wins only if:

the mean gain over 5 seeds is positive;
the 95% CI of the gain (paired bootstrap on test, 1,000 resamples) excludes 0;
the gain is positive for at least 4 seeds out of 5.

Otherwise the conclusion is "no demonstrated difference". Phase C results are never used to change a choice.

Metrics
Metric	Role
PR-AUC	Main metric
Recall at 5% FPR	Business metric (BAF paper)
Precision, recall, F1, confusion matrix	Complementary, at the chosen threshold
ROC-AUC	Never used alone
Training / generation / prediction time	Cost

Accuracy is never used: with 1% fraud, it reaches 99% for a model that detects nothing.

Synthetic data quality is assessed on six dimensions: fidelity (KS, Wasserstein, TVD, correlation gaps, SDMetrics score), detectability (C2ST), validity (types, bounds, categories), diversity (duplicates, mode collapse), utility (E3/E4) and privacy (DCR vs. a real reference, exact copies).

Fairness

Following BAF's official code, applicants are split into two groups: under 50 and 50 and over. We report the FPR ratio (lowest FPR / highest FPR, 1 = fair) at the global 5% FPR threshold (predictive equality), for each strategy E1–E3.

An observed gap is a statistical finding, not proof of discrimination nor a legal conclusion.

Explainability and LLM assistant
SHAP: global feature importance and local explanations for at least 10 alerts.
LLM assistant: rephrases the top-5 SHAP contributions in French for a fraud analyst. It decides nothing.
Verifier: output is a JSON validated by a Pydantic schema; any answer citing a factor outside the top-5 SHAP, a wrong value or a wrong effect direction is rejected.
Evaluation on ≥ 200 alerts: prompt only (no SHAP) vs. prompt with SHAP context, including no-information cases where the correct answer is to abstain. Reported: compliance rate, invented-factor rate, correct abstention.
Default LLM: open-source, local (Ollama). An API is used only if approved by the instructor.

Installation

Target: a laptop with 4 cores, 16 GB RAM, no GPU (free Colab / Kaggle GPU as fallback for TabDDPM).

bash
git clone https://github.com/<organisation>/BankSynth-AI.git
cd BankSynth-AI
python3.11 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
Download the data

With the Kaggle CLI configured:

bash
kaggle datasets download -d sgpjesus/bank-account-fraud-dataset-neurips-2022 -f Base.csv -p data/raw
unzip data/raw/Base.csv.zip -d data/raw   # if Kaggle returns a zip
sha256sum data/raw/Base.csv               # compare with docs/data_card.md
Secrets

API keys (if any) go in a .env file, which is git-ignored. Never commit keys or raw data.

Usage

🚧 Commands below are the planned interface (one command per pipeline step, configured by YAML). They will be updated as modules are merged.

bash
python -m banksynth.data.prepare      --config configs/data.yaml        # split + preprocessing
python -m banksynth.generators.train  --config configs/generators.yaml  # train generators, sample ratios
python -m banksynth.evaluation.quality --config configs/quality.yaml    # synthetic data quality report
python -m banksynth.models.benchmark  --config configs/benchmark.yaml --phase A   # then B, then C
python -m banksynth.evaluation.fairness --config configs/fairness.yaml
python -m banksynth.explain.run       --config configs/explain.yaml     # SHAP + LLM + verifier
streamlit run app/Home.py                                               # demo app

Run the tests and the linter:

bash
pytest
ruff check .

Limitations
BAF is already synthetic: conclusions must be confirmed on real data (ULB replication is future work).
Known limits of tabular GANs: mode collapse, instability, poor rare-class coverage.
Privacy measures (DCR, exact copies) are empirical and do not replace differential privacy.
Fraud detection is excluded from the EU AI Act high-risk category, but we voluntarily apply its good practices: transparency, bias measurement, human oversight, documentation.
